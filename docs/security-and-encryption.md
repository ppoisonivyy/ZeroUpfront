# Security and encryption in the hospital workspace

ZeroUpfront handles insurance identifiers, health records, financial decisions and original PDFs. Each hospital gets a dedicated database. A shared web service can route staff to their hospital, and a hospital can also run its own installation. A signed-in coordinator can see that hospital’s cases. A real pilot needs a hospital-approved access model and evidence from the selected host. The release and its benchmarks use synthetic records. [Hospital deployment](deployment.md) · [Country and recipient decisions](privacy-by-jurisdiction.md)

## Who can open a submitted preauthorization?

A coordinator signs in to the hospital queue. An insurer reviewer signs in with a separate account at that hospital. The server looks up the reviewer’s assigned payer for each request. The reviewer can read submitted revisions for that payer and their PDFs, and can ask a question about a page in that submitted packet. Hospital staff can answer. The conversation is bound to the submitted revision and leaves the signed form intact. A replacement report, a draft, or another hospital’s submission requires its own authorized handoff. Password resets preserve the assignment and revoke active sessions. [Access tests](../tests/test_staff_access.py) · [Handoff tests](../tests/test_preclaim_handoff.py)

## What protects each copy?

| Data or connection | What the release does | What the hospital or host must establish |
| --- | --- | --- |
| Staff browser and API | Remote staff login requires HTTPS. An authenticated HTTPS session uses an HttpOnly, Secure, SameSite=Strict cookie scoped to the API. A local synthetic rehearsal can use loopback HTTP. | Configure and renew a trusted edge certificate, use TLS 1.3 where supported with TLS 1.2 as the minimum compatibility version, set HSTS at the HTTPS edge, restrict forwarded headers to trusted proxies, and authenticate and encrypt any network hop from the proxy to the API. [TLS guidance](https://cheatsheetseries.owasp.org/cheatsheets/Transport_Layer_Security_Cheat_Sheet.html) |
| API to PostgreSQL | The release image defaults libpq to `sslmode=verify-full` for TCP. The container smoke test trusted a dedicated database certificate, observed TLS 1.3 on the actual SQL session, rejected an unrelated certificate authority, and exercised the staff workflow. The local rehearsal uses a private Unix socket. | Mount the provider’s trusted CA, set the DNS name covered by its certificate, and restrict network access. Explicit connection settings can override environment defaults. Check the effective settings on the deployed service and every worker. [PostgreSQL connection modes](https://www.postgresql.org/docs/18/libpq-connect.html) · [Smoke test](../bench/container_release.py) |
| Original PDFs, OCR, case metadata and ledger | PostgreSQL holds the original bytes and readable structured evidence. PDF SHA-256 digests identify source bytes and support revision and export checks. Anyone granted the necessary database read privileges can read the content. | Use managed encryption at rest for data, indexes, WAL, replicas, snapshots and backup storage. Keep keys and key-management permissions separate from data operations, record key access, rotate keys and test restore with the intended key and recovery identity. Check the named host’s actual settings. For example, encrypted RDS uses AES-256 and KMS. [Stored representation](../app/workspace_store.py) · [PostgreSQL encryption options](https://www.postgresql.org/docs/current/encryption-options.html) · [RDS encryption scope](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Overview.Encryption.html) |
| Temporary files, logical dumps and exports | Upload processing can spool file contents. A custom-format `pg_dump` and a downloaded reviewed PDF are independently readable files. Storage encryption on the primary stops at that boundary. | Use private encrypted scratch storage or memory-backed temporary space with a concurrency and memory budget. Encrypt dump destinations, restrict exports on managed endpoints, govern retention and test recovery. Include backup copies, cross-region restores and support access in the hospital's transfer review. |
| Staff passwords and sessions | The pinned Argon2 implementation hashes passwords with Argon2id. The explicit RFC 9106 low-memory profile uses 64 MiB, three iterations, parallelism four and a fresh 16-byte salt. A session uses 32 random bytes and PostgreSQL stores its SHA-256 lookup digest. Sessions expire after eight hours and reset, disable or logout revokes applicable sessions. | Provision individual accounts, integrate hospital SSO and MFA for a pilot, and test revocation on every replica. Size login concurrency for the memory cost. [Staff implementation](../app/staff_access.py) · [Argon2 recommendations](https://www.rfc-editor.org/rfc/rfc9106.html) · [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) |
| External AI | Digital intake works with cloud features disabled. Enabled OCR sends chosen page PDFs. A confirmed second read sends the revision’s document set and scoped metadata through the provider’s HTTPS API. Both request `store=False`. The model service processes readable inputs. | Approve the exact recipient, endpoint, model, location, retention and contract. Review support and subprocessors. A billing credit or per-request storage setting provides no evidence of a BAA or project-level zero retention. [Data flow and contracts](privacy-by-jurisdiction.md) · [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data) |

A hospital that needs the database administrator to lack access to original PDFs should evaluate application-side envelope encryption. Each object would receive a data key, encrypted under a separately controlled regional KMS key. The application would authenticate and decrypt only an authorized revision, then check the original-byte digest. The current application does not implement that design. Searchable identifiers, derived text, exports and working memory need their own exposure analysis. Use a maintained authenticated-encryption library or provider SDK and document how old keys remain available for permissible restores. [Cloud KMS envelope encryption](https://docs.cloud.google.com/kms/docs/envelope-encryption) · [OWASP cryptographic storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)

## Source audit and release changes

On November 21, 2026, a Standard Codex Security scan with an independent source reviewer examined the tracked application at the revision below. Three medium findings concerned how ordinary hospital workflows handle sensitive or expensive input. The review covered staff access, PDF routes, storage, optional model calls, browser search and deployment defaults. Production perimeter configuration, third-party systems and patient records were outside the inspected environment. [Audited source revision](https://github.com/aowngong/ZeroUpfront/tree/c8eb9a12b41d8874c3d3777cd31bff16dcce01e8)

| Finding | Control and remaining operational work |
| --- | --- |
| Search terms could enter access logs in request URLs. | The browser now sends free-text search in a JSON POST body. The paged GET endpoint rejects nonempty search text. Default app launches omit raw request logs. Configure gateways, traces and error reporters to omit bodies, cookies, query strings, filenames and raw resource paths. Record route templates, status, duration and appropriate pseudonymous event IDs. An operator who controls an existing installation should review previous logs and their retention. [Browser request](../web/src/DischargeQueue.tsx) · [Logging guidance](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html) |
| The per-PDF size check ran after multipart parsing. | A total-body check now bounds declared and streamed multipart uploads before parsing. The limit is 97 MiB, allowing four 24 MiB PDFs plus form overhead. The separate per-file limit still applies. Ingress must bound simultaneous uploads, read time and scratch capacity. [HTTP guards](../app/workspace_http_common.py) · [Regression checks](../tests/test_upload_limit.py) |
| A retry could repeat hosted OCR while creating one case. | For keyed OCR intake, admission and discharge coordinate through PostgreSQL before evaluation. A completed matching packet replays its saved first revision. A concurrent caller can receive HTTP 409 and a Retry-After interval, and a reused key with different content is rejected. The browser supplies keys for new cases. [Intake regression tests](../tests/test_intake_idempotency.py) |

An OCR-enabled intake occupies a database transaction and connection until evaluation and the save finish. Set per-hospital OCR concurrency below the database budget and ensure database and proxy timeouts allow the approved operation. Digital intake has no need to hold a connection while computing its findings. Calls without an idempotency key are independent. A crash after the provider receives a request and before PostgreSQL commits can still cause a repeat on retry. For longer jobs and tighter egress accounting, adopt a durable job record, provider correlation and explicit recovery for ambiguous completion. [Scaling limits](scaling.md)

## Password storage and database inputs

Each password set or reset uses a fresh random salt. The encoded Argon2id verifier contains its parameters and salt, which allows verification without a recoverable password. Independent salts prevent reuse of precomputed rainbow tables across accounts. Memory and iteration costs also slow guessing against a single stolen verifier. Login error responses omit supplied credentials. [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html) · [Password and session regression tests](../tests/test_staff_access.py)

A source review traced the application's PostgreSQL execution calls. Login names, worklist filters, case IDs, document lookups and write values use psycopg parameters. Worklist SQL composes a fixed internal projection. The local example launcher quotes database identifiers using `sql.Identifier` and selects the names from its fictional hospital mapping. Literal apostrophes, percent signs and underscores are covered by regression checks. Future query changes require the same review. [psycopg parameter binding](https://www.psycopg.org/psycopg3/docs/basic/params.html) · [Data store](../app/discharge_store.py) · [Hospital isolation tests](../tests/test_hospital_platform.py)

## Remaining controls for identifiable records

1. **Limit access by job.** Define who can read each case, approve revisions, record receipts and perform administrative support. Add least-privilege roles, MFA, break-glass controls and periodic review. Keep hospital database credentials and routing separate across deployments.
2. **Record disclosures.** Existing signed-in actions and revisions support reconciliation. A pilot also needs protected records for reads, downloads, external AI disclosures and support access. Record actor, purpose, case reference, recipient and time with restricted access and a retention schedule. Keep clinical contents out of general telemetry.
3. **Prove infrastructure settings.** Retain dated configuration evidence for TLS, storage and backup keys, private network paths, regional IAM, secrets, compute and upload limits. Restore synthetic originals and compare hashes. Rehearse key rotation, loss of a replica, revocation and a privacy incident.
4. **Validate hospital obligations.** Agree on notices, data rights, records schedules, legal holds, overseas access and notification owners. Recheck when adding another hospital, payer, replica region or model vendor. [Privacy decision guide](privacy-by-jurisdiction.md)

NIST CSF 2.0 provides a common way to track governance, protection, detection, response and recovery across hospitals. Each jurisdiction and treatment relationship still determines the legal and contractual requirements.
