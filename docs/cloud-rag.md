# OpenAI-hosted retrieval for ZeroUpfront

These research CLI runs on 21 November 2026 tested OpenAI-managed policy retrieval, an explicit embedding reranker, Astra page transcription and Astra drafting. The released discharge workspace screens original exhibits locally and offers an optional multimodal second read. The hosted policy index belongs to the separate policy experiments. [Run the workspace](../README.md#run-the-demo) · [Discharge reader design](payer-review-design.md) · [Bilingual retrieval comparison](embedding-eval.md)

The policy CLI defaults to full-edition evidence for its two short policies. The managed pipeline below remains available with `--policy-context search`. [Direct comparison](benchmark-comparison.md)

## What to host

The preparation CLI indexed the two eight-page fictional policy editions in one expiring OpenAI vector store. It attached 16 text files, one per passage in these fixtures, with edition, digest, passage reference and physical page. Each direct search filters on edition and digest and checks its hits against the local source manifest. It then reranks with an explicit Embeddings API call and sends up to four policy passages plus the bounded case exhibits to Astra. The store holds policy material. Original PDFs stay in the checkout. The current case is supplied to inference during the live run. Responses File Search is another possible integration, with search invoked from the model call. [Retrieval guide](https://developers.openai.com/api/docs/guides/retrieval) · [File Search](https://developers.openai.com/api/docs/guides/tools-file-search)

The deterministic calculator reconciles known packet formats. The policy CLI verifies that the model returns the same typed amount and that its quotations occur on the cited pages. The managed Thai scan run produced a verified **THB 141,800** staff draft in **20.180 seconds**. The original six-case suite passed **6/6** on its separate live checker. These observations cover CLI preparation. [End-to-end evidence](document-research.md) · [Financial baseline](finance-gate.md)

**Future runtime option.** The OpenAI Agents API can host the model/tool loop and session. An optional OpenAI-hosted sandbox can execute scripts or create artifacts, which the team could evaluate for a document-processing job. The application still decides which cases a staff member can access, starts work, receives results, and implements its own function tools. The released browser workspace serves its own UI and manages case revisions, original PDFs and staff approvals. The prep CLI calls Responses, Embeddings and vector stores directly. ## Embedding selection

| Choice | Controls available to the team | Consequence |
| --- | --- | --- |
| OpenAI-managed vector store | Chunking, file attributes, scope filters, result count, ranking options and expiration. Ranking can combine semantic and keyword matches. | OpenAI controls the index embeddings. The public store create, file attach and search contracts expose no model or dimensions selector. Treat the embedding model as an implementation detail. [Create store](https://developers.openai.com/api/reference/resources/vector_stores/methods/create) · [Search store](https://developers.openai.com/api/reference/resources/vector_stores/methods/search) |
| Explicit Embeddings API for reranking or an application-controlled index | Pass the embedding model and optional dimensions on each embedding request. | The tested reranker selects text-embedding-3-large at its default 3,072 dimensions. It scores the query and policy candidates and fuses their cosine rank with the hosted search rank. The comparison uses text-embedding-3-small at its default 1,536 dimensions. SQLite is used only by the local index comparison. [Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create) · [Vector embeddings guide](https://developers.openai.com/api/docs/guides/embeddings) |

The experiment used Python SDK version 3.57.0 to inspect these contracts. Its typed `VectorStores.create`, `Files.create` under vector stores, and `VectorStores.search` signatures expose no embedding model/dimensions parameter. `Embeddings.create` requires `model` and accepts `dimensions`. An Astra model selection on the generation request controls the answer model. A published example using a particular embedding model to illustrate similarity does not establish a current hosted model setting.

For explicit embeddings, OpenAI reports aggregate MIRACL scores of 44.0 for small and 54.9 for large. MIRACL includes Thai retrieval over Wikipedia. These are aggregate multilingual results across general passages. Measure Thai-only, English-only and cross-language questions against unseen insurance editions, including rider exceptions and wrong-edition distractors. Score whether **all controlling pages** appear in the evidence set, along with supported abstentions, citation correctness, latency and cost. A higher aggregate benchmark score alone cannot tell the team which approach retrieves Thai benefit-table footnotes more reliably. [OpenAI benchmark](https://openai.com/index/new-embedding-models-and-api-updates/) · [MIRACL paper](https://aclanthology.org/2023.tacl-1.63/) · [MIRACL Thai corpus](https://github.com/project-miracl/miracl)

## Retention and cleanup

Vector-store application state persists until deletion or configured expiry. Setup configures a seven-day store expiry from last activity and a 30-day file expiry from creation. It records the store ID locally. For an operating service, retain the backing file IDs alongside the policy revision to support earlier removal. Store expiration ends charges for its expired indexed files. Removing a file from a store is eventually consistent, and detaching the file leaves the uploaded Files API resource in place. Delete the underlying file separately after confirming whether other stores use it. Apply an application-side active-edition check immediately when withdrawing a policy, including while deletion propagates. OpenAI's endpoint table lists vector stores as ineligible for Zero Data Retention. Keep original-file retention, API application state, abuse-monitoring retention and third-party backups distinct when discussing a pilot. [Retention controls](https://developers.openai.com/api/docs/guides/your-data) · [Store expiry and eventual consistency](https://developers.openai.com/api/docs/guides/retrieval) · [Detach versus delete](https://developers.openai.com/api/reference/resources/vector_stores/subresources/files/methods/delete)

## Reranking decision

Use the built-in automatic ranker and the tested explicit embedding pass for exploratory bilingual search on the demo editions. On mostly English policy wording, hosted search alone found complete evidence for 15/16 English questions and 1/16 Thai questions. Including verified additional candidates from the short edition and reranking with explicit large embeddings produced 16/16 and 14/16, respectively. A separate reranking service adds another dependency without evidence here that it improves the outcome. For supported insurance checks, resolve the applicable base clause and required exceptions from the versioned rulebook, then open or cite their source pages directly.
