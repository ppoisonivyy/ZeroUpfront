# OpenAI-hosted retrieval for ZeroUpfront

Research checked 21 November 2026. This decision record describes the hosting options. See the [document benchmarks](document-research.md) for results from the separate application-controlled retriever.

## What to host

For a cloud demo that minimizes infrastructure, use an OpenAI vector store for the **policy library**. OpenAI accepts policy files, parses and chunks them, computes and stores embeddings, and serves retrieval. The backend can explicitly search the selected edition and pass the returned excerpts to Astra. Responses also offers a hosted File Search tool that performs retrieval inside a model run. Direct retrieval gives the backend the evidence list up front for page-level citation checks. [Retrieval guide](https://developers.openai.com/api/docs/guides/retrieval) · [File Search](https://developers.openai.com/api/docs/guides/tools-file-search)

Keep the original PDF and a mapping from indexed file IDs to source revision, SHA-256 and physical page. For the demo, one text artifact per source page makes the mapping unambiguous. Extract or OCR the policy first, attach insurer and edition as file attributes, wait for indexing to complete, and filter on the selected edition before searching. A returned file citation identifies an indexed file. The application can resolve the page, verify quoted text against that revision, and open the original PDF. The proposed FastAPI service, staff authentication, case database, original-document storage, job processing and review UI each need an application deployment. Keep patient case exhibits scoped to their own case. [Store-file attributes and indexing](https://developers.openai.com/api/docs/guides/retrieval) · [File citation format](https://developers.openai.com/api/docs/guides/tools-file-search)

## Embedding selection

| Choice | Controls available to the team | Consequence |
| --- | --- | --- |
| OpenAI-managed vector store | Chunking, file attributes, scope filters, result count, ranking options and expiration. Ranking can combine semantic and keyword matches. | OpenAI controls the index embeddings. The public store create, file attach and search contracts expose no model or dimensions selector. Treat the embedding model as an implementation detail. [Create store](https://developers.openai.com/api/reference/resources/vector_stores/methods/create) · [Search store](https://developers.openai.com/api/reference/resources/vector_stores/methods/search) |
| Explicit Embeddings API with an application-controlled index | Pass the embedding model and optional dimensions on each embedding request. | The current candidates are text-embedding-3-small at 1,536 default dimensions and text-embedding-3-large at 3,072. Choose this route if controlling or benchmarking the vector model is a product requirement. Record model, dimensions and source revision in the index version. [Embeddings API](https://developers.openai.com/api/reference/resources/embeddings/methods/create) · [Vector embeddings guide](https://developers.openai.com/api/docs/guides/embeddings) |

The installed Python SDK, version 3.57.0, agrees with the published contracts. Its typed `VectorStores.create`, `Files.create` under vector stores, and `VectorStores.search` signatures expose no embedding model/dimensions parameter. `Embeddings.create` requires `model` and accepts `dimensions`. An Astra model selection on the generation request controls the answer model. A published example using a particular embedding model to illustrate similarity does not establish a current hosted model setting.

For explicit embeddings, OpenAI reports aggregate MIRACL scores of 44.0 for small and 54.9 for large. MIRACL includes Thai retrieval over Wikipedia. These are aggregate multilingual results across general passages. Measure Thai-only, English-only and cross-language questions against unseen insurance editions, including rider exceptions and wrong-edition distractors. Score whether **all controlling pages** appear in the evidence set; also score supported abstentions, citation correctness, latency and cost. A higher aggregate benchmark score alone cannot tell the team which approach retrieves Thai benefit-table footnotes more reliably. [OpenAI benchmark](https://openai.com/index/new-embedding-models-and-api-updates/) · [MIRACL paper](https://aclanthology.org/2023.tacl-1.63/) · [MIRACL Thai corpus](https://github.com/project-miracl/miracl)

## Price and credit scope

| Meter | Published standard price |
| --- | --- |
| Hosted vector-store storage | First 1 GB free across stores; $0.10 per additional GB per day, based on indexed chunks and embeddings. |
| File Search invoked as a Responses tool | $2.50 per 1,000 calls, plus applicable model usage. OpenAI scopes this call price to Responses. Its Retrieval guide publishes storage pricing for direct vector-store search. |
| Explicit embeddings, on the application-controlled route | $0.02 per million input tokens for small; $0.13 for large. Provision and pay for the application-controlled index separately. |
| Astra OCR and generation | Standard short-context GPT-6.2 Astra text rates are $8 per million input tokens and $40 per million output tokens. PDF inputs also consume tokens for page images. Use actual usage and billing records to measure per-case cost. |

For example, 2 GB of total indexed storage held for 30 days plus 100 hosted File Search tool calls amounts to **$3.25** in these two line items, assuming the full 1 GB allowance is available. The example excludes the other model calls, original storage and app hosting. ## Retention and cleanup

Vector-store application state persists until deletion or configured expiry. Set an appropriate `expires_after` and keep a manifest of store IDs and uploaded file IDs. Store expiration ends charges for its expired indexed files. Removing a file from a store is eventually consistent, and detaching the file leaves the uploaded Files API resource in place. Delete the underlying file separately after confirming whether other stores use it. Apply an application-side active-edition check immediately when withdrawing a policy, including while deletion propagates. OpenAI's endpoint table lists vector stores as ineligible for Zero Data Retention. Keep original-file retention, API application state, abuse-monitoring retention and third-party backups distinct when discussing a pilot. [Retention controls](https://developers.openai.com/api/docs/guides/your-data) · [Store expiry and eventual consistency](https://developers.openai.com/api/docs/guides/retrieval) · [Detach versus delete](https://developers.openai.com/api/reference/resources/vector_stores/subresources/files/methods/delete)
